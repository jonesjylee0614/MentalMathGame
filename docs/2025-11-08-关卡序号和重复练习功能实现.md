# 关卡序号和重复练习功能实现

**日期**: 2025-11-08  
**功能**: 添加关卡序号显示和重复练习功能

## 📋 需求背景

1. **关卡序号不显示**：页面没有显示关卡在其分类中的序号（第几关），用户无法直观了解关卡位置
2. **无法重复练习**：孩子无法重复玩相同的关卡进行专项训练，不利于知识巩固

## ✅ 实现功能

### 1. 关卡序号显示

#### 关卡列表页面 (`LevelsPage.tsx`)
- ✅ 每个关卡卡片顶部显示"第 X 关"标记
- ✅ 显示游戏模式图标和名称（战斗、收集、钓鱼等）
- ✅ 添加游戏模式图标映射函数 `getGameModeIcon()`
- ✅ 添加游戏模式名称映射函数 `getGameModeName()`

#### 游戏页面 (`PlayPage.tsx`)
- ✅ 顶部状态栏显示"第 X 关"标记
- ✅ 添加 `getLevelNumber()` 函数获取关卡在分类中的序号
- ✅ 优化标题布局，序号和关卡名称并排显示

### 2. 重复练习功能

#### 关卡状态展示
- ✅ 已完成的关卡显示绿色背景和"✓ 已完成"徽章
- ✅ 显示关卡进度信息：
  - 最高分
  - 最高正确率
  - 练习次数
- ✅ 已完成关卡的按钮文字改为"🔁 重复练习"
- ✅ 未完成关卡的按钮文字为"🎮 开始挑战"

#### 进度数据集成
- ✅ 使用 `GameContext` 中的 `progress` 数据
- ✅ 根据 `lastOutcome === 'victory'` 判断关卡是否完成
- ✅ 显示关卡的最佳成绩和历史记录

### 3. UI/UX 优化

#### 关卡卡片样式
- ✅ 关卡序号：橙色渐变徽章，醒目显示
- ✅ 游戏模式：白色背景小标签，带图标
- ✅ 完成徽章：绿色渐变，右上角显示
- ✅ 已完成关卡：绿色背景渐变
- ✅ 进度信息卡片：三栏布局，展示关键数据

#### 交互优化
- ✅ 卡片悬停效果：已完成关卡显示绿色阴影
- ✅ 按钮文字动态变化，清晰表达功能
- ✅ 进度信息仅在已玩过的关卡显示

## 🔄 重复练习机制

### 核心逻辑
1. 用户完成关卡后，关卡状态标记为"已完成"
2. 已完成关卡显示历史最佳数据
3. 点击"重复练习"按钮可再次进入关卡
4. 每次游戏记录都会更新进度数据
5. 系统保留最高分、最高正确率等数据

### 数据结构
```typescript
interface ProgressEntry {
  levelId: string;           // 关卡ID
  bestScore: number;         // 最高分数
  bestTimeSec: number;       // 最佳用时
  bestAccuracy: number;      // 最高正确率
  playCount: number;         // 游玩次数
  lastPlayedAt: number;      // 最后游玩时间
  lastOutcome?: 'victory' | 'defeat' | 'timeout';  // 最后结果
}
```

## 📊 技术要点

### 状态管理
- 使用 `GameContext` 统一管理用户进度
- `progress` 数组存储所有关卡的游玩记录
- 自动同步本地存储和会话数据

### 性能优化
- 使用 `useMemo` 避免不必要的计算
- 条件渲染减少DOM节点
- CSS过渡动画提升流畅度

### 代码复用
- 游戏模式映射函数可在多处复用
- 关卡序号计算逻辑封装为独立函数
- 样式模块化，便于维护
