# 心算游戏后端开发规划

## 1. 项目概述

### 1.1 项目背景
心算闯关游戏（Mental Math Arena）目前是纯前端应用，数据存储在浏览器的 localStorage 和 sessionStorage 中。为了支持以下功能，需要添加后端服务：

- **多设备数据同步**：用户可以在不同设备上登录，访问同一个游戏账号
- **排行榜系统**：全局/关卡排行榜，增强社交竞技性
- **数据持久化**：防止浏览器清除缓存导致数据丢失
- **用户管理**：注册、登录、个人资料管理
- **数据统计分析**：后台统计用户行为、游戏数据，优化题目难度
- **成就系统**：全局成就、每日任务
- **家长模式**：家长账号关联子账号，查看学习报告

### 1.2 技术选型
- **后端语言**：Go 1.21+
- **Web 框架**：Gin (轻量、高性能、中间件丰富)
- **ORM 框架**：GORM 2.0 (功能完善、社区活跃)
- **数据库**：MySQL 5.7
- **缓存**：Redis (用于 token、排行榜)
- **认证方案**：JWT (无状态、适合前后端分离)
- **API 文档**：Swagger/OpenAPI

## 3. 数据库设计

### 3.1 核心表结构

#### 3.1.1 用户表 (users)
```sql
CREATE TABLE users (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '用户ID',
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    email VARCHAR(100) NOT NULL UNIQUE COMMENT '邮箱',
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
    nickname VARCHAR(50) NOT NULL COMMENT '昵称',
    avatar_url VARCHAR(255) DEFAULT '' COMMENT '头像URL',
    role ENUM('student', 'parent', 'admin') DEFAULT 'student' COMMENT '角色',
    parent_id BIGINT UNSIGNED DEFAULT NULL COMMENT '家长ID（用于家长模式）',
    status TINYINT DEFAULT 1 COMMENT '状态：0-禁用，1-正常',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    last_login_at TIMESTAMP NULL COMMENT '最后登录时间',
    INDEX idx_username (username),
    INDEX idx_email (email),
    INDEX idx_parent_id (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

### 3.2 索引优化策略
- 用户表：username、email 唯一索引
- 游戏记录表：user_id、level_id、created_at、score 组合查询优化
- 关卡进度表：user_id + level_id 联合唯一索引
- 排行榜查询：game_records.score + created_at 复合索引

## 4. API 接口设计

### 4.1 API 设计原则
- RESTful 风格
- 统一响应格式
- 版本控制（/api/v1）
- 错误码规范
- 请求限流
- 幂等性保证

### 4.2 统一响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1702345678
}
```

错误响应：
```json
{
  "code": 400,
  "message": "参数错误",
  "errors": [
    {
      "field": "username",
      "message": "用户名长度必须在 3-20 之间"
    }
  ],
  "timestamp": 1702345678
}
```

## 5. 认证授权方案

### 5.1 JWT 认证流程
1. 用户登录 → 服务器验证 → 生成 JWT Token
2. 客户端存储 Token（localStorage 或 sessionStorage）
3. 后续请求携带 Token：`Authorization: Bearer <token>`
4. 服务器验证 Token → 提取用户信息 → 处理请求

### 5.2 Token 设计
```json
{
  "header": {
    "alg": "HS256",
    "typ": "JWT"
  },
  "payload": {
    "user_id": 12345,
    "username": "player123",
    "role": "student",
    "exp": 1702345678,
    "iat": 1702259278
  }
}
```

### 5.3 Token 管理
- **有效期**：7 天（可配置）
- **刷新机制**：Token 过期前 1 天可刷新
- **黑名单**：Redis 存储已登出的 Token（可选）

### 5.4 权限控制
- **学生角色**：只能访问自己的数据
- **家长角色**：可访问关联子账号的数据
- **管理员角色**：可管理用户、关卡配置

## 6. 前后端交互流程

### 6.1 用户注册登录流程
```
用户 → [注册] → 后端验证 → 写入数据库 → 返回成功
用户 → [登录] → 后端验证 → 生成 JWT → 返回 Token
前端 → 存储 Token → 自动登录 → 获取用户信息
```

### 6.2 游戏流程（推荐方案）
```
前端：
1. 用户选择关卡
2. 前端生成题目（保持现有逻辑）
3. 用户答题，前端计算分数
4. 游戏结束，前端提交结果到后端

后端：
1. 接收游戏结果
2. 基础验证（分数合理性、时间合理性）
3. 更新用户进度、统计数据
4. 检测成就、任务完成情况
5. 返回结果（奖励、排名变化等）
```

**优点**：
- 保持前端题目生成逻辑，无需后端重写
- 减少网络请求，游戏体验更流畅
- 后端只做验证和数据持久化

**防作弊措施**：
- 基础合理性验证（分数不能超过理论最大值）
- 时间验证（不能小于理论最短时间）
- 异常检测（连续高分、异常行为标记）
- 重要赛事可改为后端生成题目模式

### 6.3 数据同步流程
```
用户登录 → 后端返回用户数据
前端 Context 初始化 → 优先使用服务器数据
游戏过程 → 前端实时更新 UI
游戏结束 → 提交到服务器 → 更新本地缓存
离线模式 → 使用 localStorage → 登录后同步
```

### 6.4 离线模式支持（可选）
```
前端检测网络状态
在线：正常调用 API
离线：使用 localStorage
网络恢复 → 同步离线数据到服务器
```

#### 7.3.2 JWT 认证中间件
```go
// internal/api/middleware/auth.go
func AuthMiddleware(jwtSecret string) gin.HandlerFunc {
    return func(c *gin.Context) {
        token := c.GetHeader("Authorization")
        if token == "" {
            c.JSON(401, gin.H{"code": 401, "message": "未登录"})
            c.Abort()
            return
        }
        
        // 验证 Token
        claims, err := jwt.ValidateToken(token, jwtSecret)
        if err != nil {
            c.JSON(401, gin.H{"code": 401, "message": "Token无效"})
            c.Abort()
            return
        }
        
        // 将用户信息存入上下文
        c.Set("user_id", claims.UserID)
        c.Set("username", claims.Username)
        c.Set("role", claims.Role)
        c.Next()
    }
}
```

### 8.6 新增认证上下文 (AuthContext.tsx)
```typescript
import { createContext, useContext, useState, useEffect } from 'react';
import { authApi } from '../api/auth';

interface AuthContextValue {
  isAuthenticated: boolean;
  user: User | null;
  login: (username: string, password: string) => Promise<void>;
  logout: () => void;
  loading: boolean;
}

const AuthContext = createContext<AuthContextValue | undefined>(undefined);

export const AuthProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
  const [isAuthenticated, setIsAuthenticated] = useState(false);
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);
  
  useEffect(() => {
    // 检查是否已登录
    const token = localStorage.getItem('auth_token');
    if (token) {
      // 验证 Token 并获取用户信息
      fetchUser();
    } else {
      setLoading(false);
    }
  }, []);
  
  const login = async (username: string, password: string) => {
    const response = await authApi.login({ username, password });
    localStorage.setItem('auth_token', response.data.token);
    setUser(response.data.user);
    setIsAuthenticated(true);
  };
  
  const logout = () => {
    localStorage.removeItem('auth_token');
    setUser(null);
    setIsAuthenticated(false);
  };
  
  return (
    <AuthContext.Provider value={{ isAuthenticated, user, login, logout, loading }}>
      {children}
    </AuthContext.Provider>
  );
};

export const useAuth = () => {
  const context = useContext(AuthContext);
  if (!context) throw new Error('useAuth must be used within AuthProvider');
  return context;
};
```

## 11. 数据迁移方案

4. **批量上传**：调用 `/api/v1/users/me/migrate` 接口
5. **验证同步**：后端返回同步结果
6. **清理旧数据**：同步成功后清理 localStorage（可选保留备份）

## 12. 安全考虑

### 12.1 密码安全
- 使用 bcrypt 加密，cost 因子设为 12
- 密码强度验证（至少 8 位，包含大小写字母、数字）
- 限制密码重试次数（5 次/15 分钟）

### 12.2 防 SQL 注入
- 使用 GORM 参数化查询
- 输入验证（正则表达式、白名单）

### 12.3 防 XSS
- API 返回数据转义（GORM 自动处理）
- 前端使用 React（自动转义）

### 12.4 防 CSRF
- JWT 本身防 CSRF（不使用 Cookie）
- 关键操作添加二次验证

### 12.5 请求限流
- 使用 `golang.org/x/time/rate` 或 Gin 中间件
- Redis 存储访问计数

### 12.6 敏感信息保护
- JWT Secret 使用环境变量
- 数据库密码使用环境变量
- 生产环境禁用 Debug 模式

## 17. 附录

### 17.1 错误码规范
```
2xx：成功
200：请求成功
201：创建成功

4xx：客户端错误
400：请求参数错误
401：未登录/认证失败
403：无权限
404：资源不存在
409：资源冲突（如用户名已存在）
429：请求过于频繁

5xx：服务器错误
500：服务器内部错误
502：网关错误
503：服务不可用
```

### 17.2 数据库命名规范
- 表名：小写，下划线分隔，复数形式（users、game_records）
- 字段名：小写，下划线分隔（user_id、created_at）
- 索引：`idx_表名_字段名`（idx_users_username）
- 外键：`fk_表名_字段名`（fk_game_records_user_id）

### 17.3 API 版本管理
- URL 路径版本：`/api/v1/...`
- 大版本变更时创建新路径：`/api/v2/...`
- 旧版本保留 6 个月过渡期
