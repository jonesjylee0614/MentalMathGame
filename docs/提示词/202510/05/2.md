
# 🎯《Mental Math Arena》关卡答题页优化说明（dev4 版本改进方案）

---

## 一、总体目标

实现一个**逻辑正确、战斗感强、平板端体验流畅**的答题闯关页面。
强化“打怪”式反馈、明确操作逻辑、统一视觉焦点，提升沉浸感和节奏感。

---

## 二、交互逻辑修正

### ✅ 1. 输入答案逻辑优化

当前问题：点击数字键后页面直接跳到下一题，**未显示输入内容，也无提交确认**。

**修正方案：**

* **输入过程：**

  * 点击数字按钮后 → 数字逐步显示在「输入答案框」中。
  * 支持多位数输入（例如 10、12 等）。
  * 提供「清空」键用于重置输入框。
* **提交逻辑：**

  * 只有点击【提交】按钮才判定答案。
  * 判定正确/错误后再切换下一题。
  * 点击提交前禁用自动跳题。
* **输入框交互：**

  * 为空时显示灰色占位字“请输入答案”；
  * 有输入时字体放大、高亮显示，增加输入确认感。

## 三、布局重构（核心结构调整）

### 🎨 新结构概览

```
----------------------------------------------
| 顶部状态区：关卡名 + 倒计时 + 战斗状态       |
|---------------------------------------------|
| 花 🌻   [血条]——HP百分比——[血条]   👾 僵尸   |
|---------------------------------------------|
| 主区：左（题目）    |    右（输入区）         |
|---------------------------------------------|
| 左侧：4 + 3 = ?                              |
| （大字体、动画、题号在左上角）               |
|---------------------------------------------|
| 右侧：数字键盘 + 输入框                     |
|---------------------------------------------|
| 底部：进度 / 正确率 / 连击 + 按钮栏          |
----------------------------------------------
```

**说明：**

* 整体采用 **上下分两层、主区左右分栏** 的结构。
* 战斗区（角色+血条）固定在顶部一整行；题目和操作集中在中间；状态与按钮在底部。
* 所有关键内容（题目、输入、血量）在一屏内显示，无需滚动。

## 四、战斗动画与角色表现（重点）

### ⚔️ 战斗区交互逻辑

| 状态   | 动画行为             | 效果说明           |
| ---- | ---------------- | -------------- |
| 答对   | 僵尸扣血、僵尸闪红、花微笑或眨眼 | 怪物血条动画减少（0.3s） |
| 答错   | 花扣血、花闪红、僵尸挑衅动作   | 我方血条减少（0.3s）   |
| 血条显示 | 位于角色头顶上方，左右对称    | 绿色=我方，红色=敌方    |
| 战斗结束 | 角色进行胜利或失败动作      | 胜利：僵尸倒地；失败：花枯萎 |

**动画建议：**

* 动效类型：CSS + Lottie JSON
* 动作节奏：闪烁 0.2s + HP条动画 0.5s
* 过渡缓动：`ease-out`
* 攻击特效：可加一条“能量线”从一方击向另一方（简短、可复用）

## 五、题目与输入区改进细节

| 模块     | 改进建议                | 实现说明           |
| ------ | ------------------- | -------------- |
| 题目显示   | 字体放大至 64–72px，加粗，居中 | 保持屏幕中央焦点，提升识别度 |
| 题号标识   | 左上角显示 “第 n / 20 题”  | 保持学习节奏感        |
| 输入框    | 点击数字后即时显示内容         | 防止用户误操作        |
| 提交按钮   | 高亮绿色（成功感）           | 点击后触发判断逻辑      |
| 键盘交互   | 按键轻缩放 + 阴影          | 模拟实体按压手感       |
| 禁用重复输入 | 提交时临时禁用键盘 0.5 秒     | 防止连点造成状态错乱     |

## 六、顶部信息区优化

| 元素   | 优化方案                        |
| ---- | --------------------------- |
| 倒计时  | 保留圆环倒计时，移动至中上方中央，视觉焦点清晰     |
| 血条行  | 花🌻 左、僵尸👾右，中间为血量条（绿色/红色渐变） |
| 状态文本 | 下方显示 “击败僵尸！” 或 “继续战斗！” 动态文本 |

---

## 七、底部状态栏优化

| 模块   | 优化方案                   |
| ---- | ---------------------- |
| 数据统计 | 只保留核心三项：进度 / 正确率 / 连击  |
| 文案引导 | 如“再答 20 题即可获胜！” 根据实时更新 |
| 按钮区  | 【返回关卡】【退出】【提交答案】保持居中对齐 |

---

## 八、额外发现与建议

| 问题        | 建议                         |
| --------- | -------------------------- |
| 倒计时重复两次显示 | 合并为一个全局倒计时组件，避免UI冗余        |
| 背景色层次不足   | 增加柔光渐变（橙-浅粉），让角色和题目更突出     |
| 缺乏动感提示    | 每题切换时可加“翻页”或“滑入”过渡动画       |
| 声效        | 增加点击/答对/打击音效，增强沉浸感         |
| 数据持久化     | localStorage 保存本关成绩，用于统计界面 |

## 九、开发验收标准

✅ 输入数字后实时显示，点击提交后再进入下一题；
✅ 战斗区单行显示，角色左右分布、血条动画正常；
✅ 题目与输入区左右对齐，保证一屏完整显示；
✅ 答对/答错有即时动画反馈（HP变动+动作特效）；
✅ 所有按钮触控区 ≥ 48px，触摸延迟 < 100ms；
✅ FPS ≥ 55，动画总时长不超过 800ms；
✅ 页面在 10–12 寸平板上横竖屏均适配。
